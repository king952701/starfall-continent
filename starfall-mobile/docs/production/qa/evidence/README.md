# 证据规范（production/qa/evidence）

## 原则（来自工作室三条不可协商原则）

1. **跑起来亲眼看**：改动玩家能看到/听到的东西，关闭前必须真正运行并观察，证据落本目录。
2. **解析通过 ≠ 看起来对**：`node --check` 与用例全绿不等于画面正确。
3. **没有观察工具就如实说**：本机无浏览器/截图工具时标注 `NOT ASSESSED`，**不得伪造观察结论**。

## 现有观察能力（本机实测）

| 能力 | 状态 |
|---|---|
| Node 无头用例（桩 DOM/Canvas/AudioContext，加载全部 src） | ✅ 可用，已用于游泳/船只/分隔条 |
| `node --check` 语法检查 | ✅ |
| GitHub Actions 出 APK + 包内 zip 自检 | ✅ |
| 浏览器截图 / Playwright | ❌ 未安装 → 视觉项只能靠真机或标注 NOT ASSESSED |
| 音频实际听感 | ❌ 无播放 → 只能断言"调用了正确音色/参数"，听感需真机 |

## 命名

```
<批次>-<StoryID>-<简述>.md / .png
例：p1-A2-战斗音效-call-sequence.md
```

## 每个 Story 的证据最低要求

| 类型 | 要求 |
|---|---|
| 逻辑类（数值/状态机/节流/并发） | 无头用例输出（含 PASS 行）粘贴到证据文件 |
| 视觉类（画面/人物/地图/树图） | 真机截图；无工具则 `NOT ASSESSED` + 说明替代验证手段（如像素对照、参数断言） |
| 音频类 | 调用序列 + 参数断言（音色名/音高/节流计数）；听感标 `NOT ASSESSED` 待真机 |
| 构建类 | Actions run 链接 + 包内自检清单（如 `assets/www/...` 条目） |

## 回归基线（每次出包前必跑）

- 全量 `node --check` 通过
- 无头启动用例：Game 构造 + 一帧 update + 一帧 render 不抛异常
- 既有功能用例：游泳状态、水域碰撞、船只上下船、分隔条挂载
